## Phase Goal

**As a** Home Assistant user, **I want to** add an XMLTV source (URL or local file) in the HA UI and attach calendars filtered by channel and include/exclude regex, **so that** I see exactly the matching programmes as correctly timed calendar events that drive my calendar-trigger automations.

(Story assembled from the ROADMAP Phase 1 Goal and the PROJECT.md Core Value; the ROADMAP Goal line itself is not yet in user-story form.)

<objective>
Walking skeleton for the whole integration: the thinnest production-quality path from the HA UI to a calendar entity. A user adds a URL source through the config flow, adds one calendar subentry that picks channels, and sees the feed's programmes as calendar events. Every layer the phase touches exists after this plan: scaffold (uv, Ruff, pytest harness), manifest, source fetch, coordinator, the pure `xmltv/` library (model, timestamps, normalization, streaming parser, filter, rendering, window reads), calendar entity, both flows and translations.

Later plans fill functionality behind the contracts created here without changing them: full timestamp variants and stop inference (01-02), include/exclude/channel-regex semantics (01-03), indexed and capped reads (01-04), gzip/caps/fetch hardening (01-05), file sources and duplicate protection (01-07), and the full calendar form (01-08).

Purpose: prove the architecture end to end (source entry + calendar subentries + one shared coordinator) before any expansion work.
Output: a loadable `xmltv_calendar` integration, a green end-to-end tracer test, and the test harness every later plan reuses.

Sizing (plan-checker scope_sanity): the tracer task creates 20 files because a walking skeleton needs one module per layer of the wave-2 file-ownership contract.
