## Phase Goal

**As a** Home Assistant user with filtered XMLTV calendars, **I want to** automate around matches beyond plain calendar triggers (next-match sensor, new-match event, recent past matches, ready-made blueprint) and install a documented, bilingual, tagged release via HACS, **so that** I can act on the programmes I care about without hand-built polling automations and keep the integration up to date.

<objective>
Fire an HA event `xmltv_calendar_new_match` when a new matching programme appears in the feed (EVT-08, D-07..D-13): one event per new match, never for what a calendar starts with, never again after a restart, capped per refresh. The seen-set lives in a persisted per-source match store that 04-06 extends with retained past matches (ROADMAP note: EVT-07 and EVT-08 share one store).

Purpose: "tell me when a new Formula 1 broadcast is announced" without polling the calendar.
Output: pure seen-set module, MatchStore, refilter reasons in the calendar, store lifecycle in __init__.py, tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Feed content -> event bus | A third-party feed decides how many new UIDs appear per refresh and what the event text contains |
| .storage file -> MatchStore | The persisted seen-set may be corrupt or hand-edited |
| Event payload -> user automations | Payload values feed notifications and templates |
