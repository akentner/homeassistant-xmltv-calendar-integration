## Phase Goal

**As a** Home Assistant user with XMLTV sources, **I want to** have each source cached across restarts, refreshed on my own schedule and only when the feed changed, tolerant of failures and timezone quirks, editable later, and visible when something goes wrong, **so that** every calendar stays populated at minimal network and CPU cost.

(Story text reused verbatim from 03-01..03-08.)

Gaps closed by this plan: 03-VERIFICATION.md `gaps[2]` (WR-02, 03-07 truth 3, roadmap SC 5) and `gaps[3]` (WR-03, 03-01 truth 11).

<objective>
TDD gap closure for WR-02 and WR-03.

1. WR-02: a source created through the setup flow starts from the flow-seeded cache (`_async_start_from_cache`), which never records a success, and `_async_seed_cache` writes only the payload and `CacheMeta`. `health.last_success` therefore stays None until the first scheduled refresh (up to 168 h or a day later): diagnostics show `last_success: null` for a working source, and a failure streak starting at that first refresh raises a Repairs issue saying "Last successful refresh: -". This is the normal user path. Fix in the flow: after a successful cache write, save `SourceHealth(last_success=fetched_at)` with the same `fetched_at` as the metadata.
2. WR-03: `tests/test_identity.py` loads `fixtures/basic.xml` (programmes on 2026-10-13) without freezing the clock. Since 2026-10-14 18:15 UTC (the last fixture stop plus KEEP_PAST of one day) the parser drops every programme, the entries sit in SETUP_RETRY, and the tests still pass because they only assert on flow results. Fix: freeze the module like the other fixture modules and assert that each created entry is LOADED.

Purpose: SRC-12 promises diagnostics with the last success, and the Repairs text (D-18) names it; both must be right for the normal setup path. The identity tests must fail loudly when time-dependent fixtures expire.
Output: a seeded health in `config_flow._async_seed_cache`, new assertions and one new test in tests/test_config_flow.py, a frozen tests/test_identity.py with LOADED assertions.
</objective>

## Planner Decisions (Claude's discretion, all reversible)

- **Seed in the flow, not adopt in the coordinator.** The verifier allows either. Adopting `meta.fetched_at` in `_async_start_from_cache` would add a second health-writing path to the coordinator. It would have to fill only `last_success` and leave a real failure streak alone (a streak recorded after a seed must survive restarts), and it would put this plan on the same file as 03-09, forcing a second wave. Recording the success where it happens (the setup download) is exact and keeps both plans in wave 1. Store shape and `SourceHealth` fields are unchanged. Rating: reversible.
- **WR-03 RED depends on the wall clock by design**: it demonstrates the defect (SETUP_RETRY after the fixtures expired) before the freeze removes the dependency.
