<objective>
Fix code review finding WR-05 (phase 02): escape_markdown in custom_components/xmltv_calendar/xmltv/preview.py lets line breaks through, so feed text can break the preview Markdown list. Collapse every whitespace run to a single space, and strip the edges, at the start of escape_markdown. A preview line is single-line by definition. One TDD cycle: a failing end-to-end flow test plus unit cases first, then the fix.

Origin: .planning/phases/02-precise-filters-preview/02-REVIEW.md, WR-05. The user chose to fix this before closing phase 02. Two inputs carry line breaks into the preview unchanged. The channel display name keeps an internal \n, because parser._text strips only the edges and channel names never pass through clean_title. The title keeps a \r after clean_title, which replaces only \n. The joined list then splits into separate lists, an ordered list, or an <hr> (verified by the reviewer with marked 17.0.5, gfm + breaks).

Purpose: the preview keeps showing "one line per match" (FLT-10, D-17) for any feed text, and feed text can no longer fake extra preview lines.

Output: the escape_markdown change in preview.py, one flow test in tests/test_subentry_flow.py, and unit tests in tests/xmltv/test_preview.py. RED evidence goes under .planning/quick/261015-u6j-collapse-line-breaks-in-preview-feed-tex/tdd-evidence/.
