## Phase Goal

**As a** Home Assistant user, **I want to** pinpoint specific shows with field-scoped, Unicode-safe regex plus duration and time-window filters, shape event titles and descriptions with templates, check the matches in a preview before saving, and retune any calendar instantly, **so that** each calendar shows exactly the programmes I care about, clearly titled, without re-downloading the source.

(Story text reused verbatim from 02-01..02-09. The ROADMAP Goal line itself is a capability statement, not a user story; see 02-VERIFICATION.md "Mode".)

Gap closed by this plan: 02-UAT.md gap **G-02-2** (UAT test 2, minor): a bare URL in a feed title is autolinked in the preview. Folded in at the user's request: review finding **IN-04** (02-REVIEW.md): `escape_markdown` does not escape `~`, so `~~x~~` is struck through. It is the same function and a one-character change.

<objective>
TDD gap closure for G-02-2 plus IN-04. The preview menu description is Markdown rendered by the HA frontend. `escape_markdown` (xmltv/preview.py:24-36) already neutralises HTML and the Markdown syntax characters, but it misses two things:

1. **GFM autolinks.** marked, in its GFM mode, turns three plain-text forms into clickable links even without any Markdown syntax: `scheme://…` (http, https and ftp, in any letter case), `www.…`, and e-mail addresses (also the `mailto:` and `xmpp:` forms).
2. **GFM strikethrough with `~`** (IN-04).

The fix stays inside `escape_markdown`:
- `~` joins `_MARKDOWN_CHARS`.
- A new compiled pattern `_AUTOLINK_TRIGGERS` puts one backslash in front of the single punctuation character each autolink form depends on: the `:` of `://`, the `.` of `www.` and every `@`.

A backslash before ASCII punctuation is a CommonMark escape. The renderer drops it and shows the bare character, so the preview text still reads exactly like the feed text.

Purpose: the T-02-05 intent ("feed text renders literally in the preview") holds for every GFM inline extension that the HA frontend's marked applies to plain text. FLT-10's preview shows feed data, never feed-controlled links.
Output: changes to preview.py, new pure tests in tests/xmltv/test_preview.py, and one end-to-end flow test in tests/test_subentry_flow.py.
</objective>

How the HA frontend renders the preview (checked during planning against the frontend in the ha-dev container, HA 2026.10.1, home-assistant-frontend 20260930.3):
- `renderMenuDescription` localizes `config.step.preview.description` with the description placeholders and renders it as `<ha-markdown allow-svg breaks>`. ha-markdown calls the markdown worker (`frontend_latest/markdown-worker.*.js`) with `{breaks: true, gfm: true}`. The worker runs marked, then js-xss `filterXSS` with a whitelist that keeps `a href`. There is no extra linkify step.
- marked's GFM inline `url` rule in that bundle has three alternatives:
  - `emailProtocol`: `mailto:` or `xmpp:` plus an address.
  - A scheme alternative: `[hH][tT][tT][pP][sS]?|[fF][tT][pP]` followed by `://`. The scheme is case-insensitive.
  - A `www.` alternative (lower case only in this version).
  - A bare e-mail alternative, which needs a literal `@`.
- The GFM text rule stops in front of `://` and `www.` anywhere in a word. That is why `wwww.x.de` links its `www.x.de` part, and `first_last@x.de` links `last@x.de` after the existing `\_` escape.
- `del` matches both `~x~` and `~~x~~`.
- The escape rule accepts `\` followed by any ASCII punctuation, including `:`, `.`, `@` and `~`, and emits just the character.

Mechanism choice (Claude's discretion, decided while planning):
- **Chosen: a backslash in front of the trigger punctuation.**
  - It uses the same mechanism as every existing escape in this function, and the UAT already showed that backslashes survive `hass.localize`.
  - It renders the original characters, so a URL copied from the preview is the real URL.
  - Tests assert plain ASCII.
- **Rejected: zero-width characters (U+200B, U+2060) inside `://` or `www.`.** They stop marked just as well, but they stay invisible in the rendered text and in copy/paste. Copied URLs would silently break, and test strings would carry invisible characters.
- **Rejected: escaping every `:`, `.` and `@`.** It would change many existing preview strings, for example "Channel: Running" and "Formel 1: Großer Preis", and their test assertions, for no rendering gain.
- **Targeted triggers:**
  - The `:` before `//` covers every scheme, regardless of letter case.
  - The `.` after `www` is matched case-insensitively. This marked version only links lower-case `www.`, but older marked versions compiled the URL rule with the `i` flag, and the escape renders the same either way, so over-escaping costs nothing.
  - Every `@` covers both e-mail alternatives.
  - Bare domains without `www.` (e.g. `ard.de`) are never autolinked by marked, so they need nothing.
