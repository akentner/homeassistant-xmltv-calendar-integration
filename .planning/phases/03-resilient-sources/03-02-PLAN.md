## Phase Goal

**As a** Home Assistant user with XMLTV sources, **I want to** have each source cached across restarts, refreshed on my own schedule and only when the feed changed, tolerant of failures and timezone quirks, editable later, and visible when something goes wrong, **so that** every calendar stays populated at minimal network and CPU cost.

<objective>
Cache the raw feed on disk so that an HA restart or an entry reload fills the calendars without a download while the cache is fresh (SRC-06, D-08, D-09). A stale cache is shown at once and refreshed in the background (stale-while-revalidate, RESEARCH Pattern 3), so a slow or unreachable host never blocks or fails setup when cached data exists. The cache is validated against the entry's source and its stored size, written only after a good parse, private on disk, free of the URL, and deleted with the entry.

Purpose: today every restart, every reload and every option change downloads and parses the full feed (tens of MB). This plan removes that cost; 03-03 adds conditional requests on top.
Output: cache.py, Fetched in source.py, coordinator cache path, async_remove_entry, the calendar availability override, tests/test_cache.py.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
