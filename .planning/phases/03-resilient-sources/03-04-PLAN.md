## Phase Goal

**As a** Home Assistant user with XMLTV sources, **I want to** have each source cached across restarts, refreshed on my own schedule and only when the feed changed, tolerant of failures and timezone quirks, editable later, and visible when something goes wrong, **so that** every calendar stays populated at minimal network and CPU cost.

<objective>
Make failures harmless and visible. A failed fetch or parse keeps the last good data and the calendars keep working (SRC-08, D-19). The source retries with a capped backoff (D-10). A source that has kept failing for more than 24 h, counted from the first failure of the streak, raises one info-only Repairs issue naming the source, the last success and the reason; the next success clears it (SRC-11, D-17, D-18). A feed with zero programmes counts as a failure (D-20). Failure state is persisted, so restarts and setup retries neither hide nor reset it.

Purpose: EPG hosts go down and generators emit empty files. Calendar triggers drive recordings and notifications, so the calendars must not go blank, and the user must learn about a dead source without reading logs.
Output: SourceHealth persistence, coordinator health/Repairs/backoff/empty-feed logic, issue and exception translations (en + de), Repairs, backoff and empty-feed tests, two test-fixture updates.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Coordinator -> Repairs UI | Issue texts and placeholders are shown to every admin and may end up in screenshots and bug reports |
| Feed host failures -> retry loop | A failing host decides how often the integration retries |
| Store -> coordinator | Persisted health may be corrupt or hand-edited |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-12 | Information disclosure | coordinator._sync_issue placeholders and issue translations | high | mitigate | Placeholders are limited to the entry title and a formatted time; reasons are fixed translation keys, never exception text (test_issue_text_has_no_url) |
| T-03-13 | Denial of service | failure retry scheduling | medium | mitigate | backoff_delay starts at 5 min and grows to 6 h, capped by the regular schedule, so a dead host is never polled in a tight loop (test_failure_backoff_steps) |
| T-03-14 | Tampering | SourceHealth.from_dict | low | mitigate | Tolerant reader: malformed or hand-edited health gives the default state, never an exception at setup |
| T-03-15 | Denial of service | Store writes per refresh | low | accept | One small JSON save per refresh outcome; refreshes are at most hourly or follow the backoff |
| T-03-SC | Tampering | uv dev installs | high | mitigate | No packages added; issue_registry is a Home Assistant built-in |
</threat_model>
