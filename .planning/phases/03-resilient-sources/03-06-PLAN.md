## Phase Goal

**As a** Home Assistant user with XMLTV sources, **I want to** have each source cached across restarts, refreshed on my own schedule and only when the feed changed, tolerant of failures and timezone quirks, editable later, and visible when something goes wrong, **so that** every calendar stays populated at minimal network and CPU cost.

<objective>
Rebuild the source setup flow. The url and file steps ask for the refresh mode and the timezone options (D-01, D-05, D-14, D-15); a schedule step then shows only the field the mode needs (D-01, D-02). For URL sources the full download runs behind a progress step (CFG-03) and seeds the disk cache, so the entry starts without downloading the feed again (D-13). Errors return to the url step with the input kept. All callers of the old one-step flow move to shared test helpers.

Purpose: a 50 MB feed takes a while; the user should see that something happens, and the feed should be downloaded once, not twice. Schedule and timezone belong in setup so the very first parse is right.
Output: config_flow.py builders and steps, translations (en + de), removal of async_probe_url, flow tests and helpers.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin input -> flow | URL, path, schedule and timezone values typed into the setup form |
| Feed host -> flow download | Untrusted body and size, during an interactive flow |
| Flow -> cache | The flow persists the downloaded body before the entry exists |
