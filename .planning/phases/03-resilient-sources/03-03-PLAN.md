## Phase Goal

**As a** Home Assistant user with XMLTV sources, **I want to** have each source cached across restarts, refreshed on my own schedule and only when the feed changed, tolerant of failures and timezone quirks, editable later, and visible when something goes wrong, **so that** every calendar stays populated at minimal network and CPU cost.

<objective>
Refresh only what changed. URL sources send the stored validators and treat a 304 as "unchanged": no body, no parse, no refilter (SRC-07). A byte-identical 200 is not re-parsed either. `homeassistant.update_entity` on any calendar refreshes its source at once, still with validators (AUT-04, D-12). Local files are re-parsed only when their mtime or size changed, with the allowed-path check on every refresh (D-11). Calendars refilter only for new data.

Purpose: a daily feed checked hourly, or a user pressing "update", should cost one small request, not a 50 MB download plus a multi-second parse and a refilter of every calendar.
Output: conditional GET in source.py, the later-refresh decision in the coordinator, FeedCache.async_touch, the file signature skip, the calendar identity guard, tests/test_refresh.py, tests/test_file_source.py.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Feed host -> coordinator | Status codes, validators and bodies are untrusted |
| Local file system -> coordinator | A configured path may leave the allowlist or change at any time |
| UI/automation -> update_entity | Any user or automation can request refreshes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-09 | Denial of service | coordinator 304 handling | low | mitigate | Validators are sent only with a valid payload on disk; a 304 without data parses the cache and otherwise repeats the request unconditionally, so a 304 never leaves the source empty (test_304_without_usable_cache_refetches_unconditionally) |
| T-03-10 | Elevation of privilege | read_and_parse_file | medium | mitigate | check_file runs before the stat on every refresh, also when the file is unchanged, so a path removed from allowlist_external_dirs or turned into an escaping symlink is refused (test_allowed_path_checked_on_every_refresh) |
| T-03-11 | Denial of service | homeassistant.update_entity | low | accept | The coordinator debouncer (10 s cooldown) collapses bursts; each request is conditional, so a burst costs small 304 answers, not downloads |
| T-03-SC | Tampering | uv dev installs | high | mitigate | No packages added |
</threat_model>
