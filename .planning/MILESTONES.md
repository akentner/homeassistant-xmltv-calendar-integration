# Milestones

## v1.0.1 v1.0 Release (Shipped: 2026-10-30)

**Phases completed:** 5 phases, 47 plans, 113 tasks

**Key accomplishments:**
- Every XMLTV timestamp variant now lands at the correct UTC instant. That covers 12-digit, `+HH:MM`, no-space, alpha zones, and no offset (treated as UTC). Missing or broken stops are inferred from the next later start on the same channel. Exact duplicates collapse. Each event carries a stable `<channel>-<UTC start>-<crc32>` UID. All four RED targets failed on their planned assertions before GREEN.
- `FilterSpec` now applies the full D-02 to D-08 rule: channel (selected IDs OR channel-ID regex, both empty = all) AND (include empty OR any include line) AND NOT any exclude line. Each pattern is tested case-insensitively against the title and each sub-title on its own. `first_invalid_pattern` enforces 300-character and 50-line caps, and `missing_channels` only names IDs the feed truly lacks. Both RED/GREEN cycles were classified `RED_EVIDENCE_OK`.
- A bisect-based MatchIndex now serves calendar reads. get_events is capped at 5,000 events, and slices over 200 are built in the executor. Invalid matches are skipped. HA tests drive real calendar triggers (start with -5 min offset, end exactly on a 15-minute window boundary) and live on/off state.
- Gzip is now detected by its magic bytes, not the URL or Content-Type. Decompressed XML is capped at 1 GiB and downloads are streamed with a 256 MiB cap and timeouts. Every broken, truncated or hostile payload becomes a typed, translated failure (`feed_too_large`, `unable_to_fetch`, `invalid_feed`) without feed content, and the previous data stays in place. Programme-only channels are listed under their ID.
- The repository is now a valid HACS custom integration: hacs.json, brand icons, MIT license and README are in place, and the official hassfest container reports 0 invalid integrations. Two SHA-pinned, least-privilege workflows (Validate: hassfest + HACS; CI: Ruff, unit, benchmark) are guarded by offline structure tests. A seeded 60 MB feed generator backs SRC-09 with measured numbers: 80,773 programmes, a 102 MB tracemalloc peak, and a maximum event-loop gap of 86-164 ms against a 250 ms limit.
- Local XMLTV files (plain or gzip, any name) can now be added as sources, and they are read only from directories Home Assistant allows. Every source gets a hashed, normalized identity (`sha256("url:"/"file:" + locator)`), so the same source added twice aborts with `already_configured`. Bad URLs, unreachable hosts, non-feeds, disallowed or missing paths and blank names are refused in the flow with translated errors. The URL probe reads at most 64 KiB.
- The Add calendar form now takes channel regex, include and exclude as multiline pattern fields. Each line is validated with `first_invalid_pattern` before anything is stored, so a bad line shows `invalid_regex` with the line and the regex error. A 10-test lifecycle suite proves that several calendars share one download and can be added, removed and renamed live.
- ha-dev now runs HA 2026.10.1 with xmltv_calendar mounted read-only from the working tree. Four feeds dated today sit read-only under /media/xmltv, startup logs are clean, and the integration parses all four feeds inside the container runtime (60 MB plain in 2.8 s). By the user's decision there is no real German excerpt (D-15 deferred). A skip-guarded real-feed acceptance suite is ready for one, and the UI walkthrough is queued for UAT.
- Public repo akentner/homeassistant-xmltv-integration with anonymized history, green CI (Ruff, unit, 60 MB benchmark) and Validate (hassfest, HACS) for HEAD ffd5363, and the HACS custom-repository check queued for UAT
- `parse_xmltv_time` now range-checks offsets (minutes < 60, magnitude <= 18 h) and years (1900..2200) and never raises. The parser skips any programme whose conversion fails and only reports genuine read/decode failures as `FeedError`. The calendar skips matches that cannot become a `CalendarEvent`. One broken `<programme>` can no longer reject a feed, crash `parse()` or crash event building.
- Calendar subentry edits now apply in place through the single diffing listener. The entity rebuilds its own FilterSpec and re-filters `coordinator.data` with no download, parse or reload. Title edits rename the device. Corrupt stored patterns keep the previous matches. MatchIndex lookups clamp near `datetime.min` (IN-14).
- Include and exclude now match only the fields each calendar chooses (title, sub-title, description, category). Each sub-title and each category is tested on its own. There is a case-sensitive toggle, and feed text and patterns are NFC-normalized, so umlauts match whether they are composed or decomposed. All of this sits on a new pure contract module, `xmltv/settings.py`, which defines every stored Phase 2 calendar setting and reads it tolerantly.
- Calendar subentry flow now goes basic -> preview menu (match count from now on plus the next 10 lines in local HA time, German or English weekdays, escaped feed text) -> Save | Back, with a translatable empty-preview warning. The preview is computed in the executor using the entity's own FilterSpec.
- Half-open local start-time window with midnight anchoring, weekdays and inclusive min/max duration, all evaluated in HA's time zone for both entity and preview, plus a fail-open `re._parser` walk that rejects nested unbounded repetition.
- Calendars can now be edited from the HA UI. `async_step_reconfigure` reuses the basic -> preview -> save path, pre-filled from the stored subentry, and saves through `async_update_and_abort`, so the 02-01 in-place listener applies the change without re-downloading, re-parsing, reloading or touching sibling calendars. Every save now writes the full 14-key stored contract.
- Restricted `{placeholder}` templates compiled once with `string.Formatter().parse` and rendered by joining parts. They shape event titles with D-22 edge cleanup and descriptions with the D-23 default layout. The calendar entity and the flow preview share one `EventTemplates` rendering path.
- "Advanced options" subentry step with field-scope, case, time-window, weekday, duration and template inputs, plus one-pass validation (fields_required, time_incomplete, time_equal, duration_order, invalid_template, unknown_placeholder) and translated selector labels.
- Editing a calendar with stored advanced settings now opens with "Advanced options" checked (has_advanced in the run-once _load_pending), backed by regression tests for unchecking, Back, the case flag, nested-repetition rejection and translation placeholders; full suite, benchmarks, Ruff and hassfest are green and the ha-dev UAT walkthrough is queued.
- One shared `PATTERN_ERRORS = (re.error, OverflowError, RecursionError)` tuple, caught in `calendar._build_spec` and `first_invalid_pattern`. A stored `a{99999999999}` or 2,000-deep nesting no longer breaks calendar-platform setup or the update listener, and a typed one shows `invalid_regex` instead of "Unknown error".
- escape_markdown now backslash-escapes the ':' of '://', the '.' after 'www' (case-insensitive), every '@' and every '~', so feed URLs, hosts, e-mail addresses and strikethrough render as literal, non-clickable text in the config-flow preview (G-02-2, IN-04)
- A source now refreshes either every N hours or once a day at a fixed time in the HA time zone. The time maths (DST slots, freshness, capped backoff, the 24 h failure test) lives in the pure, table-tested `xmltv/schedule.py`. The coordinator keeps an absolute target and converts it into `update_interval` each time HA arms its timer.
- Each URL source now caches its raw feed on disk: a private payload file under `.cache` plus URL-free metadata in an HA Store. An HA restart, an entry reload or an options change fills the calendars from that cache with no download while it is fresh. A stale cache is shown at once and refreshed about 1 s later, so an unreachable host never blocks or fails setup when cached data exists.
- Conditional GET with If-None-Match/If-Modified-Since and 304 handling, a SHA-256 skip for identical bodies, an mtime/size skip for local files, and calendars that refilter only when the coordinator returns a new EpgData object (always_update=False plus an identity guard)
- Persisted SourceHealth drives a per-source Repairs issue after more than 24 h of failures (per-reason en/de texts, no URL), a 5 min to 6 h capped retry backoff, and an empty_feed failure that never wipes the last good data
- Offset-less XMLTV timestamps can be read as HA local time (DST-aware, re-pinned to fixed offsets), and a per-source minute correction shifts every programme by absolute time. The correction is applied once at parse time for downloads, the disk cache and local files.
- URL sources are now added through url -> download progress -> schedule -> name. The full, bounded download runs as a tracked task behind `async_show_progress`, and the name step writes it to the disk cache, so a new source costs one HTTP request. File sources share the refresh-mode and timezone fields and skip the download step.
- Config entry diagnostics per source (SRC-12): URL cut to scheme+host or path to file name, effective schedule/timezone options, failure health, cache presence flags, ParseStats incl. skipped_malformed and per-calendar match counts, also for entries stuck in SETUP_RETRY
- Plain OptionsFlow (init -> schedule) built from the setup builders lets a source's refresh mode, interval or daily time and timezone settings be edited later. A save writes the complete option contract, keeps the inactive daily time, and reloads the source once from its cache through the existing diffing listener.
- `refresh_base` (2 s early-fire tolerance) keeps an early-firing HA timer from requesting a daily slot twice or retrying after 1 s. A single failure handler records every non-cancellation exception as `unable_to_fetch`, backs it off and re-raises it as `UpdateFailed`. That ends the once-per-second download loop (CR-01, CR-02).
- The setup flow now saves `SourceHealth(last_success=fetched_at)` together with the seeded cache. Diagnostics and the Repairs text name the setup download instead of `null` / `-` (WR-02). `tests/test_identity.py` runs frozen at the fixture date and asserts LOADED entries (WR-03).
- Per-calendar "Next programme" timestamp sensor fed by a dispatcher signal from the calendar and a timer at the next match start, with D-03 attributes (texts kept out of the recorder) and English/German names.
- Automation blueprint that runs actions once per matching XMLTV programme a negative lead time (default minus 10 min) before it starts, using the legacy calendar start trigger with mode queued. The default action is an if-guarded notify.send_message, and all of it is tested end to end through use_blueprint.
- Tag-triggered GitHub release workflow that rejects any tag other than v<manifest version>, runs CI and Validate as reusable workflows first, and publishes with generated notes (prerelease for -suffix tags), with its shell scripts executed and shellchecked in tests
- A new matching programme in a refreshed feed now fires one `xmltv_calendar_new_match` event, with the calendar, programme and local start/end in the payload. The per-calendar seen-set behind it is persisted in a per-source Store and pruned after one day. Events are capped at 50 per refresh. Restarts, reloads, new calendars, filter edits and timezone changes stay silent.
- Each calendar device now has a disabled-by-default "Last fetch" diagnostic sensor. It shows when the source last ran a refresh, what started it (startup, scheduled, retry, revalidate, manual) and how the run ended (outcome, HTTP status, cache handling, validators sent, bytes, programmes, channels, parse time). The record is persisted next to the source health and also appears in diagnostics as `last_attempt`.
- Matches that have ended now stay in the calendar for the calendar's `retention_days` (0..7, default 1) after the feed drops them. They are stored as raw programme data in the per-source match store and captured on every refilter, on entity removal and on HA stop, so retention of more than one day survives the parser's one-day cut-off and restarts. They merge with the feed by UID (the feed wins), get re-checked when the filter is edited, are dropped when the source's timezone options change, and show up separately as `retained` in diagnostics.
- Each calendar's advanced options now include "Keep past matches (days)" / "Vergangene Treffer behalten (Tage)": a 0..7 number box stored as the int `retention_days`, where a cleared field means the default 1. Edits apply in place through the 04-06 update listener, with no reload or download. Editing a calendar pre-fills the stored value and pre-checks Advanced when it isn't 1.
- Code-derived en/de translation completeness test (AST over config_flow.py plus the vocabularies) that found and fixed the untitled download step, a full user README for 0.1.0 with automation examples, blueprint import button and calendar limitations, and a green release gate waiting for the user's v0.1.0 tag push
- Calendar subentries now keep matching, updating sensors, announcing new programmes and retaining ended matches even when their calendar presentation is disabled.
- Configuration-time feed snapshots now establish silent baselines and recheck raw retention before newer feed programmes can announce; template-only edits render immediately without a scan.
- Six bilingual diagnostic failure states now load through HA, with code-derived completeness that catches omissions even when locale parity holds.
- Sandboxed Jinja2 engine (node/filter allow-list, literal-regex validation, legacy-syntax fallback) replacing str.format, proven by a Formel 1 prefix template through the flow, preview, storage and calendar.get_events
- Six template error reasons translated in English and German behind a TEMPLATE_ERROR_REASONS-driven completeness guard, plus a two-sample trial render in validate_template that rejects templates which compile but fail at render time
- Nine D-06 template filters (lines, first_line, split, regex_search, strip_prefix, strip_suffix, remove, time, size-guarded replace) with a chain cap of 16, literal cap of 300 and result cap of 50000 characters, proven through EventTemplates and a hostile-input corpus
- Home Assistant zone threaded through calendar events, the live event, the sensor and new-match summaries and the flow preview, so a UTC feed prints Berlin wall time in `{{ start }}` and `{{ end }}` everywhere; runtime fallbacks, single warnings and edit side effects pinned by entity-level tests
- README Templates section (variables, syntax, whitespace, 37 filters, time directives, limits, form messages, upgrade note) with four recipes that a test renders through the real engine, completeness tests that fail when a filter, variable or limit is undocumented, and the stack notes rewritten for the sandboxed Jinja engine
